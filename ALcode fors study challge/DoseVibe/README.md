# 记得吃 · DoseVibe

> 慢病用药依从性 —— Swift Student Challenge 参赛作品

一句话：**漏服之后该不该补，这一件事就足以决定 App 是帮忙还是害命。**

## 一、真实问题

中国有约 1 亿以上的慢病患者，其中相当一部分是独居或与子女分住的老人。
他们每天要吃 2-5 种药，漏服极其普遍——但市面上所有提醒类 App 的逻辑都一样：

    到点了 → 响铃 → "点击已服用"

这有三处硬伤：

1. **老人不看就划掉**。确认按钮越显眼，划得越快。
2. **一律提示"补服"**。降糖药、华法林（抗凝）、抗心律药、地高辛——漏服后自行加倍
   可能造成低血糖、出血或心律失常。**统一提示"补服"是在害人。**
3. **子女看不到真相**。他们打电话问"今天吃药了吗"，得到的是"吃了"。

## 二、作品思路（对标获奖共性）

| 获奖共性 | 本作品的对应设计 |
|---|---|
| 从具体的人的真实痛点出发 | 每天四种药、其中一种是抗凝药的独居老人 |
| 多技术串联形成叙事 | 药物分类 → 漏服分级 → 确认鉴权 → 触觉节奏 → 家属日报 |
| 端上、离线、隐私 | 健康数据最敏感；全程不出设备 |
| 无障碍设计 | 三种震动节奏让不看手机的人也知道"该吃了"还是"出事了" |
| 交互巧思 | **危险药物的漏服界面上根本没有"补服"按钮**——不是藏起来，是不存在 |

### 三个设计决定

1. **漏服分级，而不是统一提醒**
   降糖药 / 抗凝药 / 抗心律药 / 地高辛 → 只能提示"联系医生或药师"，不提供任何补服动作。
   常规慢病药 → 才给出温和的按说明书处理建议。
2. **确认要有门槛**
   默认要求家属输一次口令或用面容确认，而不是老人随手一点。
   老人的行为习惯决定了这个产品有没有用。
3. **震动也要说话**
   到点=短-短-停，漏服=更慢更沉，危险漏服=长-长-长。

## 三、代码结构

    Sources/DoseVibe/
      Medication.swift      药物分类 + 能否自行补服 + 漏服提示文案
      AdherenceEngine.swift 排时间轴、判漏服、分级建议、依从率、家属日报
      CaregiverConfirm.swift 确认鉴权（家属口令 / 生物识别）
      DoseHaptics.swift     三种触觉节奏 + 播放抽象
      DoseSamples.swift     一个典型的多病共存老人用药方案
      DoseViewModel.swift   状态与动作编排
      ContentView.swift     今日时间轴 + 红色危险横幅 + 日报分享
    Tests/                  15 个测试（含"危险药物永远不给补服建议"）

## 四、诚实边界

- **不给用药建议**，只做提醒与记录；一切以医生与说明书为准。
- 不能替代药盒，也不能替代家人。
- 药物分类是常识整理，**未经临床药师审校**——这是当前最大的短板。
- 没有接入真实用药数据（医保、处方），药单要手动录入。
