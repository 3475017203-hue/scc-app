# 等一等 · SafeHarvest

> 农药**安全间隔期**提醒 —— Swift Student Challenge 参赛作品

一句话：**这茬菜什么时候能吃？拍一下药瓶标签，手机替你数着日子。**

## 一、真实问题

「安全间隔期」是农药管理里最容易被忽视、代价最直接的一条：
最后一次施药之后必须等足够天数，作物才能采收上市。

- 小农户与大棚种植者往往**凭经验**判断，"看着没事就摘了"；
- 同一茬菜要打两三遍药，很多人**只按第一次算日子**，直接超采；
- 消费者与菜贩拿到的是已采收的菜，**完全不知道自己买了什么**；
- 结果是农残超标、禁药检出、摊位被罚、种植户失去收入。

市面上的"农残速查"类 App 查的是**买回来的菜**，
没有任何工具在管**种出来的那一批还差几天**。

## 二、作品思路（对标获奖共性）

| 获奖共性 | 本作品的对应设计 |
|---|---|
| 从具体的人的真实痛点出发 | 看得见手指甲缝里农药的种植户，和等着买菜的家庭 |
| 多技术串成一个完整叙事 | Vision 端上 OCR → 标签解析 → 日期运算 → 本地通知 → 分享卡 |
| 端上、离线、隐私 | 田间与山区常无网络；图片与记录都不出设备 |
| 交互巧思 | "**最后一次施药才作数**"——把常见的错误算法直接做进产品 |
| 诚实边界 | 读不到间隔期就**拒绝计算**，要求手填，绝不用默认值糊弄 |

## 三、核心算法

    最早可采收日 = 最后一次施药日 + 安全间隔天数

- 同作物多次施药 → 只认最后一次（IntervalEngine.window(for:crop:)）；
- 间隔期最后一天当天**不可**采收，次日才"可以吃了"；
- 采收日早于该日 → 判为违规采收，卡片顶部打红条；
- 标签读不到间隔期 → 抛错 + 手填入口，**不猜**。

## 五、下一步

1. 接入真实相机层（Playgrounds 无相机管线，已留 recognize(image:) 入口）。

### v2（本轮）

1. **离线农药小词典**（PesticideDictionary.swift）：6 种常见蔬菜农药 × 6 类作物，
   全部端上，可离线查阅。
2. **双信源交叉校验**（DictionaryCrossCheckView.swift）：OCR 会把「7 天」读成「1 天」——
   标签之外再引入一个**独立信源**，两者不一致时 App 停下来让人核对，
   **绝不静默取其一**。安全产品的价值常常就体现在它拒绝自动下结论的那一瞬间。
3. 测试 11 → 15 个（新增词典命中、不一致上报、未收录回落、该作物无条目回落）。

### v3（本轮）：把"数据从哪来"写在脸上

上一轮竞品对比给出的结论是：**我们最大的短板是数据没有权威背书**。
所以本轮给每条词典条目加上来源标注（依据 + 整理日期 + 是否经权威校对），
未经校对的条目在界面上**显著提示"请以药瓶标签为准"**。

没有来源的天数是不可信的。与其让人以为这是标准答案，
不如老老实实写清楚这是从说明书整理来的、需要核对。
测试 15 → 16 个（每条条目都必须自曝来源）。
