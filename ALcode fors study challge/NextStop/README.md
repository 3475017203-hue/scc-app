# 下一站 · NextStop

> 老人坐公交不坐过站 —— Swift Student Challenge 参赛作品

一句话：**听不清报站的人，需要另一种方式知道下一站到了。**

## 一、真实问题

县域与乡镇的公交，尤其是去**医院、菜市场、女儿家**的那几趟车，
车上坐的大多是老人。而"坐过站"的成因很少是忘了看路线：

- **耳背**：车厢广播本来就听不清，加上噪声大，报站基本等于没有；
- **眼花**：站牌看不清，路上的店名招牌也认不准；
- **不熟悉换乘**：要换乘时人挤，一下车就跟丢了。

结果不是"多坐两站"，而是**在医院门口错过了那一站**，
有些人干脆选择不到医院去看病。

而市面上的公交 App（实时公交、到站预测）全部假设一件事：
**你能看见屏幕，能听见报站，能记住线路图。**

## 二、作品思路（对标获奖共性）

| 获奖共性 | 本作品的对应设计 |
|---|---|
| 从具体的人的真实痛点出发 | 去医院的老人、一个人坐车去看病的妻子 |
| 多技术串联形成叙事 | 站点困难度建模 → 风险判定 → 分级触觉 → 大字下一站 |
| 端上、离线、隐私 | 行程记录属于个人行踪，不上传 |
| 无障碍设计 | 44 号字显示下一站；震动节奏不依赖听觉；大按钮 |
| 交互巧思 | 把「我能不能听清」变成一个开关，而不是让用户读说明书 |

### 三个设计决定

1. **站点不只是名字，还有困难度**
   没有座位、噪声大、需要换乘——这些决定了到站时会发生什么。
   到站提醒必须按**这一站的困难度**编排，而不是每站都一样。
2. **触觉强度跟着风险走**
   听得到报站 → 每站一下（轻）；听不清 → 三下一组并在前一站连响（强）。
   不用眼睛、不用耳朵，用手就能知道快到了。
3. **承认报站会被漏掉**
   lastStopHeard 记下上一站到底听没听见；
   如果没听见，App 会提醒你**确认车还在不在下一站**——
   这是坐过站最直接的一条原因。

## 三、代码结构

    Sources/NextStop/
      Route.swift            线路、站点、站点困难度（无座位 / 噪声大 / 要换乘）
      RideCoach.swift        风险判定 + 行动建议 + 触觉强度
      SampleCity.swift       一条真实的县域 7 路，终点是人民医院
      NextStopViewModel.swift 行程状态与报站记录
      ContentView.swift      44 号字下一站 + 风险卡 + 三个大按钮
    Tests/                   17 个测试（含听不清报站等于很可能坐过、换乘站要跟人群区分开）

## 四、诚实边界

- **没有真实 GPS 与公交数据**：现在用固定的县域线路数据，
  没接任何官方到站接口——县城线路往往根本没有 API。
- 定位与到站判断在真实场景下需要持续定位，会耗电、会漂移。
- 站点困难度目前是人工标注，没有采集数据支撑。
- 这个作品不能替代下车前的再次确认：任何 App 都会错，我们只是把概率降低。

## 五、下一步

1. Core Location 低功耗跟随 + 速度过滤（避免红灯停车被判为到站）。
2. 接 CoreHaptics，把三档节奏真正播出来。
3. 让社区采集站点困难度：老人在车站点一下"这里吵"，就形成数据。
4. 与《静听》《别信》共用触感资产，形成"看不见听不清也能用"的一组作品。
