# 一顿饭的来路 · MealTrace

> 儿童营养午餐的溯源与营养体检 —— Swift Student Challenge 参赛作品

一句话：**孩子今天这口菜，从哪块地来的；到日子了吗？**

## 一、真实问题

农村与乡镇小学的营养午餐问题，公众注意力集中在"有没有肉、够不够量"，
但有两件更基础的事几乎没人管：

1. **这批菜什么时候采的。** 学校采购单上写着"小白菜、青浦基地"，
   但**没有采收日期，也没有末次施药日期**。
   一批提前五天采收的菜，从表面、从价格、从检测上都看不出来。
2. **一顿饭的营养结构。** 白米饭 + 一点炒菜看起来"有菜有肉"，
   但钙与维生素 A 可能长期不足——这种问题在体检之前很难被发现。

家长能做的只有两件事：问食堂，或者自己去市场打听。都没有可依据的东西。

## 二、作品思路（对标获奖共性）

| 获奖共性 | 本作品的对应设计 |
|---|---|
| 从具体的人的真实痛点出发 | 只能把孩子交给学校、又不在孩子身边的家长 |
| 多技术串联形成叙事 | 文字/图片识别 → 溯源字段抽取 → 安全间隔期倒推 → 营养结构评估 → 家长日报 |
| 端上、离线、隐私 | 孩子的饮食记录属于家庭隐私；田间与学校常常没网 |
| 无障碍设计 | 一句话结论 + 红绿两色，家长 3 秒看懂 |
| 交互巧思 | **不判定"这顿够不够"，只指出"长期趋势里缺什么"** |

### 三个设计决定

1. **读不到就问食堂，不猜**
   "读不出来"和"读成 0 天"在食安里是两种完全不同的事。
   所以解析失败时列清单：没读到安全间隔期、没读到采收日期——而不是默认"没问题"。
2. **超期采收要能说清差几天**
   不是一句"不合格"，而是"应至少等到 10 月 12 日，实际 10 月 11 日就采了"，
   这样家长去问、去反映时，手里才有依据。
3. **一顿饭判断不了营养**
   明显不足时不说"缺钙"，而是"这是长期问题，建议和学校或医生聊一次"。
   避免制造焦虑，也避免用一顿饭吓唬人。

## 三、代码结构

    Sources/MealTrace/
      Traceability.swift  批次模型 + 安全间隔期判定
      TraceParser.swift    公示文字 → 溯源字段（容错冒号/空格/多种字段名）
      MenuNutrition.swift  营养素计算与"缺口"分级
      MealSamples.swift    两种演示批次（含一条超期）
      ContentView.swift    读字段 → 红绿判定卡 → 营养缺口 → 家长日报
    Tests/                 14 个测试（含"垃圾文本必须返回 nil""一顿低不等于缺"）

## 四、诚实边界

- 营养数据是**估算**，用于发现长期倾向，不能替代体检或医生建议。
- 溯源信息以学校公示与市场监管部门公布为准，本作品不做执法判定。
- 没有接真实二维码/摄像头链路，也没有历史数据的长期积累（"一周趋势"尚未实现）。
- 演示用的安全间隔期与营养成分都是粗略值，**未经权威数据源校对**。

## 五、下一步

1. Vision 端上 OCR 拍公示屏 + 二维码识别。
2. 本地按周聚合，形成"这一个月钙一直偏低"的趋势图——**这才是家长真正需要的**。
3. 一键把疑问发给学校与监管部门（生成结构化问询，而不是一句吐槽）。
4. 与《等一等》共用间隔期引擎，但**保持两个作品的数据来源独立**。

### v2（本轮）：一顿饭判断不了营养，一周才有答案

竞品对比给出的判断是：**"长期"恰恰是这个作品真正的价值，
而竞品完全没有**——但 v1 只做了单日，根本撑不起"长期"两个字。本轮补上：

1. **一周趋势**（WeeklyTrend.swift）：把七天聚合成"钙平均 42%、连续 7 天"。
   **判定门槛：至少 4 天记录**才允许下"长期问题"的结论——
   少于 4 天就说话，是在制造焦虑。
2. **超期采收天数**独立统计：它比营养缺口更该先管。
3. **结构化问询**（InquiryDraft.swift）：把"查一下"变成"我该问什么"——
   合规批次不生成质问性问题，只问检测报告与公示改进。
4. 测试 14 → 24 个（新增趋势天数门槛、真实缺口检出、问询不误伤合规批次）。
