# 别怕 · FallGuard

> 独居老人跌倒后的静默升级呼救 —— Swift Student Challenge 参赛作品

一句话：**摔了，先问一句，再决定要不要叫人。**

## 一、真实问题

老年人髋部骨折后的**第一个小时**决定预后，而这段时间的真实死因常常不是伤，
是**没人发现**：独居、地面凉、动不了、手机在另一间屋子。

现有的做法有两种，各有硬伤：

1. **挂绳呼叫器**：老人自己按。摔了之后手未必够得着；
   也可能一年按错几十次，家里人渐渐就不当真了。
2. **智能手环跌倒检测**：Apple Watch 已经做得相当好，但它**直接就打电话**——
   老人常常只是摔了一下自己坐起来，却在半夜里把全家人吵醒、被邻居议论。
   误报的代价在真实生活里是**社交成本**。

## 二、作品思路（对标获奖共性）

| 获奖共性 | 本作品的对应设计 |
|---|---|
| 从具体的人的真实痛点出发 | 独居、子女在外地、墙上挂着一年没按过的呼叫器 |
| 多技术串联形成叙事 | 加速度判定 → 语音问询 → 分级静默升级 → 可读的消息模板 |
| 端上、离线、隐私 | 运动数据属于健康数据，不出设备；离线可用 |
| 无障碍设计 | 语音优先（全屏大字 + 高对比），不需要盯屏幕 |
| 交互巧思 | 先问一句：把「一串闹钟」变成「一次有人负责的等待」 |

### 三个设计决定

1. **冲击 + 静止**才算跌倒
   只看冲击，放下手机也会响；只看冲击，人自己爬起来也会呼救。
   判定结果必须带理由，能让人（和评委）看懂为什么这么判。
2. **先问一句，再升级**
   三次问询，任一次有回应即中止升级。措辞刻意不问「你是不是摔了」，
   只问「能回我一句吗」——要的是回应，不是答案。
3. **静默升级，先近后远**
   同住家人 → 子女 → 急救中心，每级等 30 秒。
   未预先授权的邻里会被跳过：一次误报不该变成邻里矛盾。
   夜里先发短信、10 秒后再打电话，比直接打电话更体面。

## 三、代码结构

    Sources/FallGuard/
      FallDetector.swift   冲击 + 失重 + 静止判定，输出可解释的依据
      SampleMotion.swift   合成运动样本：走动 / 摔倒后静止 / 摔一下自己起来
      VoiceCheck.swift     问询流程与措辞、应答抽象
      Escalation.swift     分级静默升级 + 消息模板（含未授权跳过）
      GuardViewModel.swift 状态编排
      ContentView.swift    判定卡 + 问询记录 + 升级顺序
    Tests/                 19 个测试（含放下手机不触发、有回应就不升级、未授权邻里被跳过）

## 四、诚实边界

- 不能替代呼叫器、手环与 120，界面底部常驻声明。
- 阈值（2.5g 冲击、25 秒静止）是常见经验值，**未经跌倒医学或康复专业调校**。
- 没有真实传感器链路（CoreMotion 还没接），也没有通话与短信的实际发送能力，
  目前只生成可读的消息模板。
- 误报依然存在，只是被压到更少；不宣称零误报。
