# 乡音桥 · DialectBridge

WWDC Swift Student Challenge 参赛作品（v1 草案）

> 一句话：让只会说方言的老人，在 30 秒内，把"说不清的难受"变成一张医生看得懂的普通话就诊卡。

## 一、要解决的真实问题

在中国 60 岁以上人群中，方言是主要口语；在医院里，医生问"你哪里不舒服"，
老人答"心口闷、压得慌"，常常被理解成消化道问题或情绪问题，误诊风险直接落在急症上。
这不是"老年人不会用智能手机"的问题，而是**语言鸿沟**问题：

- 老人：会用方言描述症状，但说不准医学词。
- 医生：听到的是方言，无法快速归类到科室与优先级。
- 结果：分诊错、问诊反复、检查过多，医患双方都累。

已有方案（导诊机器人、通用翻译 App）要么强依赖联网，要么要求老人先打一遍普通话，
对独居、高龄、方言重的老人恰恰不可用。

## 二、作品思路（对标往届获奖作品）

WWDC 2025 / 2026 获奖作品有非常一致的共性：

| 共性 | 往届例子 | 乡音桥的对应设计 |
|---|---|---|
| 从具体的人的真实痛点出发，而非泛泛工具 | Syntaxia（ALS 言语障碍）、StutterGuide（口吃）、Zeytin | 高龄方言使用者就医难 |
| 一技多做，把多个技术串成一个完整叙事 | Screenplay Genie、Tree Buddy | Speech + 本地术语库 + 归一化算法 + 可访问性排版 |
| 完全离线、端上隐私是加分项 | 大量获奖作品强调 on-device | 端上识别 + 纯本地词表，健康数据不出设备 |
| 交互上的巧思，不只是罗列功能 | BinaryWorld、SimPredict | "说不清就直接点卡片"的双通道设计 |
| 重视无障碍 | Canopy、Allergyzz | 大字模式、VoiceOver 标签、点击即选 |

核心创新是**归一化层**（DialectNormalizer）：
不做"方言 ASR"（不可能通用），而是

1. 用设备端 ASR 拿到老人真实口语（"心口疼""哈不动""手子木掉"）；
2. 用可解释的本地词表 + Dice 二元组近音纠错，把口语映射到规范医学词；
3. 输出**双向卡片**：医生看规范词，卡片上同时保留老人的原话，差的部分由家属补齐。

## 三、代码结构

    Sources/DialectBridge/
      Dialect.swift                  方言片区、症状大类、紧急度模型
      Terminology.swift              15 条医学术语的多方言说法词库（种子数据）
      Normalizer.swift               口语 → 医学词 归一化（Dice 近音纠错，可解释）
      CarePathway.swift              症状 → 科室 / 紧急度 / 医嘱 / 大白话提醒
      VisitCard.swift                产物模型 + 纯文本导出（可分享给家属）
      SpeechService.swift            语音识别抽象 + 评委一键演示的脚本识别器
      DialectSpeechRecognizer.swift  Speech 框架端上识别封装
      BridgeViewModel.swift          流程状态机（idle → listening → confirming → card）
      Theme.swift                    老人友好的字号与配色
      ContentView.swift              首页：说 / 确认 / 点 三步
      VisitCardView.swift            大字就诊卡（可缩放、可分享）
    Tests/DialectBridgeTests/        4 个单元测试（含"不误报"测试）

## 四、迭代记录

### v1（首版）

可运行的 SwiftUI 交互闭环 + 归一化算法 + 15 条术语 + 4 个测试 + 评委演示模式。

### v2（本次优化）

1. **否定识别**（NegationCues + 窄窗口就近否定）："没有头晕"不再污染主诉，
   否定项在卡片上显式标注为"患者否认"，且不参与紧急度判定。
2. **身体示意图**（BodyMapView / BodyMap.swift）："说不清就指一指"，
   12 个部位 + 左右侧 + 医生侧位置术语 + 位置相关诊断提示，
   位置本身会把胸痛 / 腹痛的分诊优先级顶上来。
3. **术语库 15 → 30 条**，新增心悸、下肢水肿、血尿、听力骤降、吞咽困难、
   非刻意体重下降等老年人高危主诉。
4. 卡片新增"老人指认的位置"分区；测试增至 8 个。
5. 新增 [Submission.md](Submission.md) 参赛文档。

### v3

1. **兜底不丢弃**（Interpreter.swift）：归一化失败时，残余片段由
   RuleBasedInterpreter 转成「要不要是这个？」的确认卡；词库确实没有的，
   明确写进卡片「需医生补充问诊」，**不编造答案**。
2. **病程抽取**（TimelineExtractor）：「三年前」「这两天」「突然」→ 结构化病程，
   写进主诉。老人不会主动说「起病三天前」，但这句话对诊断价值极高。
3. **一卡三读**（SpeechCoach + VisitCardView）：分别读给老人（慢速大白话）、
   医生（术语）、子女（结论 + 待办）。这是本作品与通用翻译 App 的根本差别。
4. **三个真人画像**（DemoScenarios.swift）：苏州阿婆 / 广州陈伯 / 川渝家属，
   每个画像对应一种真实困境，评委可 3 分钟走完。
5. 测试 8 → 10 个；新增 [DemoScript.md](DemoScript.md) 三分钟演示脚本。

### v4

1. **演示升级为「人」**：startDemo() 现在加载完整画像（方言、年龄、台词、指认位置），
   并新增「换一个人物」与演示模式开关——评委看到的是三个真实的人，不是一串数据。
2. **家属版一页纸**（CaregiverBriefView）：就诊卡给医生，这张给不在场的子女：
   现在什么情况 / 要做的三件事 / 别做的三件事 / 一键转发与朗读。
3. **词库共建**（CorpusImport.swift + CorpusView.swift）：社区医生与方言志愿者
   粘贴「规范医学词 | 方言说法 | 大类 | 片区」即可生成可审核条目，
   也可反向导出整个词库。**每条需医生签字才进正式库**——宁可慢，不让未核对的说法污染分诊。
4. 测试 10 → 14 个（新增语料解析、非法行拒绝、导出可再导入、家属朗读稿）。

### v5

1. **社区词库真的生效**（TerminologyStore.swift）：内置词库 + 本机共建词库，
   JSON 持久化在 Documents，**完全不上传**。导入后归一化器立刻用新词条工作，
   症状卡同步变多（通过 corpusTick 驱动界面重建）。
2. **导入即去重**：同一规范词的方言说法合并进同一条，不重复建条目。
3. **词库页补全**：本机共建条目可查看、单条删除、清空，并显示存储异常。
4. 归一化器与 Interpreting 协议改为接受词库参数，模型层与语料层解耦。
5. 测试 14 → 16 个（新增共建词库生效、导入合并去重）。

### v6

1. **打字 / 家属代录**（BridgeViewModel.ingest + ContentView 输入框）：
   语音、打字、家属代录走**同一条归一化流水线**。
   没有麦克风权限、老人说不清、家属在旁边，都不再是死路——
   这是农村与病房里最常见的真实情形，v1 之前只有"说话"和"点卡片"两条路。
2. 测试 16 → 18 个（新增打字输入、字输输入同样吃共建词库）。

### v7（本轮）：一条说法要生效，得先有一个人为它签字

竞品对比指向同一个短板：**我们没有权威背书**。
乡音桥的做法是把它变成一条**流程**，而不是一句口号：

1. 社区粘进来的说法一律进入「待复核」区，**不直接生效**。
2. 医生签字（或全部通过）后才并入正式词库，并做去重合并。
3. 词库界面明确显示「已签字 N 条」，测试也守住这条线：未签字的说法不得影响归一化。

30 条内置词库我们拿不出医生背书，
但**从今天起新进来的每一条都有**。
测试 18 → 20 个（新增未签字不生效、驳回不动词库）。
