# 楼道有声 · ChargeGuard

> 楼道电动车充电的早期预警与疏散指引 —— Swift Student Challenge 参赛作品

一句话：**楼道里那点声音，是不是不对劲。**

## 一、真实问题

电动车进楼入户充电是各地整治了多年的重点，也是**居民楼火灾最常见的人为原因**。
真实发生过的案例里，几乎都重复同一条链路：

1. 有人把电动车推上楼，在楼道或家里充电；
2. 电池老化 / 充电器不合格 / 私拉电线，**没有任何人发现**；
3. 起火后，电池热失控会喷火甚至爆炸，而**楼道往往被车和杂物堵住**；
4. 浓烟封住唯一通道，高层住户失去逃生窗口。

第 2 步与第 4 步之间，往往只有几分钟。

## 二、作品思路（对标获奖共性）

| 获奖共性 | 本作品的对应设计 |
|---|---|
| 从具体的人的真实痛点出发 | 租住在老楼、楼下没有车棚、只能把车推上楼的年轻人 |
| 多技术串联形成叙事 | 声学特征判定 → 风险分级 → 人工可确认线索 → 楼层相关疏散指引 |
| 端上、离线、隐私 | 不上传任何音频，不连接任何云端 |
| 无障碍设计 | 大字、高对比，危险态一屏说完，不依赖细读 |
| 交互巧思 | **焦糊味开关**：麦克风测不到，但人能闻到 |

### 三个设计决定

1. **宁可多喊一次，也不放过一次**
   误报的代价是不对称的：误报只是白跑一趟，漏报是楼道里的火。
   所以分类器不设"忽略"选项，只给"正常 / 老化 / 疑似 / 立即撤离"四档。
2. **把人的感官放进系统**
   焦糊味是热失控最强的信号，而任何麦克风都测不到它。
   所以它被做成一个必须由人点选的开关，而不是伪装成自动检测。
3. **出事时给的是"怎么走"，不是"注意安全"**
   疏散指引按楼层与楼道是否堵塞计算：
   不坐电梯、湿毛巾低姿前进、楼道被堵时先挪车不硬推、
   高楼层 + 楼道堵塞单独拉一条最危险的组合。

## 四、诚实边界（这一节写得比功能还长）

- **这不是火灾报警器，也不做任何电气监测。**
  手机拿不到电流、电压与温度数据——这是硬件限制，不是待补的功能。
  真正能预警的是电池管理系统（BMS）与楼道烟感，**手机替代不了它们**。
- 声学判定基于合成样本与经验阈值，**未经消防专业调校**，不能作为判据。
- 疏散时间按 0.8 m/s 保守估算，**不含电梯故障、门被撬、邻居不配合**等真实变量。
- 本作品的价值是"让人早一点警觉"，而不是"保证不出事"。
